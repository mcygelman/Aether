# Security and data handling

Aether runs a loopback web server and stores workplace data and memory locally. Requests to a configured hosted model send the supplied model context to that provider; choose the provider and accessible workspace with that in mind.

Local human accounts, roles, memberships and key grants live in the installation's SQLite account store. Password records contain a random salt, PBKDF2-HMAC-SHA256 digest and iteration count (600,000); account passwords are not retained as plaintext. Existing account JSON is imported once and kept as recovery evidence. Account passwords and the API management password are separate.

On Windows, **API Keys** manages labeled provider keys. The management vault uses current-user Windows DPAPI with PBKDF2-HMAC-SHA256 password-derived entropy (600,000 iterations, a random 32-byte salt). The API management password is not saved. Its unlock is scoped to the signed-in management session and current vault revision. Separate permissions control secret management and key assignment. Assignment-only managers cannot reveal secrets; one manager's unlock does not unlock another session.

Assigned usage uses a separate current-Windows-user DPAPI-protected runtime copy, bound to the management vault revision, so it continues after restart and while management is locked. No management password is stored in that copy. Every resolution checks the initiating operator's active account and current grant; even Admin needs a usage grant. Unscoped background work cannot borrow a user's managed keys. Rotation/deletion updates subsequent use; an inconsistent runtime copy fails closed until management refreshes it. **Suspend API use** prevents subsequent assigned-key requests; **Lock management** only closes management. Requests already sent may finish. This protection relies on the Windows account and does not protect against malware or an administrator inspecting an active process. Credentials need separate setup on another machine.

Credential HTTP operations require the local settings origin, use POST bodies and disable response caching. Only an explicit Reveal or Copy action by an authorized secret manager returns a key; list responses expose no secret material. The UI clears secret inputs and does not save them in browser storage. Revealed values hide after 30 seconds, when the page is hidden, or on another vault action. Copy places a key on the system clipboard. Labels are encrypted alongside keys. Model profiles retain references rather than secrets. Saved-key provider requests require HTTPS (except literal loopback), refuse redirects and resolve current authorization for each call. Legacy environment and sealed-store credentials are restricted to Admin in managed sessions. Keep keys out of commissions, project files, source control and evidence; redaction is not proof that arbitrary user or model text contains no sensitive information.

Atelier enforces its configured call budget, consent, secret and harm boundaries and its file-tool permissions. This is not an operating-system sandbox for hostile code. Run only trusted code and review which folders and tools a mind can access.

When a mind runs tests, the test code is code a model wrote. It runs on this computer with your user rights, in the project folder that holds the tests. It receives only the operating system's basic environment variables (system folders, temporary folders, PATH and Python's text encoding), so provider keys referenced from the environment and other secrets in the server's environment are not passed to it. Give agents work you would be willing to run yourself.

Packaging selects explicit files with byte commitments and rejects recognized secret material. It does not silently strip or rewrite private content. Scan findings and artifact membership are reviewed before public release. Resident homes, private memory, local profiles, credential stores and private Git history are excluded from this package.

Stop places before backup and use the shipped preservation tools; see PUBLIC_SETUP.md. Preserve originals during recovery. Report suspected vulnerabilities privately to the maintainers through a verified project contact or private advisory; do not put secrets in public issues.


The API management password has a six-character minimum for creation/reset. Reset is destructive and available to an authorized secret manager without the old password: the manager must acknowledge deletion and provide a new password. The operation checks the reviewed ciphertext revision under the writer lock, replaces the collection and clears usage assignments. Failed validation, stale review, encryption or disk-write failure preserves the existing store. Other processes detect the changed revision. Reset does not edit model profiles or revoke credentials at the provider; re-added keys require new references and grants.

Personal Chat history, notes and scratchpads are scoped to stable account IDs. A chosen folder permits supported reads within that folder; edit proposals require opt-in and explicit application. Turning access off does not erase information already present in a conversation. Shared Creations are a deliberate copy visible to signed-in installation users; a project link does not create project-level visibility controls.

Specialist technical lessons are distinct from project-local working context and authored personality. Specialists learn directly without an approval or scoring gate. Guidance encourages reusable lessons without personal, proprietary or project details; storage separation is not a guarantee of perfect model judgment.

MCP data sources require current operator permissions and source-role access. Source managers choose the service and exposed tools; DBA accounts and service configuration enforce database permissions. Tool read-only hints are metadata. HTTP service tokens use Windows DPAPI and stay out of model context and exports; local stdio commands are a trusted administrative capability. Enabling source model use allows metadata and returned data to reach the assigned model. Current access is checked before a call and before publishing its result. Source notes, runs and saved report definitions are private local records. This release's verification used no real database MCP service.
