[ TITLE ]
Attachment, Support and Motion: Choose and Check an SVG Scene

[ PURPOSE ]
Validate SVG and preserve recovery state: a corrected failed command needs top-level retry=true.

STATUS: PILOT REVISION. The CARD is generated by the repository tool; that validates its format,
not its teaching effectiveness. Michel authorized catalog availability for the three SVG agents
on 2026-11-03. The lead selects relevant lessons through existing Tasker briefcases. Availability

[ DEFINITIONS ]
∆WMC{
CONTEXT: VISUAL_ANIMATION
SUBJECT: SHARED_CONTRACT
[DEF]
  ATTACHMENT := a feature's base overlaps, merges into or is intentionally concealed by its parent
                throughout the motion; grouping cannot repair a gap in the drawn geometry.
  SUPPORT := the requested load-bearing surface, if any; do not invent a fence for an unrelated task.
  CONTACT := a stance foot meets the declared support surface or depth band within a stated tolerance;
             a swing foot may lift. A walk should not acquire unintended whole-body flight or sinking.
  PRESENT := required parts are drawn and inspectable in appropriate poses. Planned occlusion and
             entry/exit are allowed; unexplained absence or clipping is a defect.
  RELATIVE_MOTION := displacement of the figure relative to support landmarks, not merely body bob.
  DRAWN_WRONG := geometry or layering fails before animation.
  ANIMATED_APART := correct geometry loses attachment as transforms change.
  NOT_THERE := a required feature is omitted, accidentally hidden, or unintentionally off-canvas.
}WMC

[ RECOVERY_CHECKPOINT ]
Before EVERY run_command/run_tests, inspect the latest observed state for that tool in the current
task (including retained history after a resumed wake). A final nonzero exit, timeout or missing
program leaves a pending failure even if stdout already printed PASS. read_file, write_file,
rewriting Python, or success with a different tool cannot clear it. Earlier successful recovery
does not cover a LATER failure: each new failure starts its own bounded correction episode.

State a short factual checkpoint before execution: tool, pending yes/no, correction number if any.
If no failure is pending, omit retry or use false. If correcting a pending failed operation, build
the tool envelope FIRST with TOP-LEVEL JSON BOOLEAN "retry": true, then add argv/cwd or target.
Inspect the outer JSON once more before sending. For example, correcting a failed XML check:
{"retry": true, "argv": ["python", "-B", "-c", "import xml.etree.ElementTree as E; E.parse('cat.svg')"]}
This is not an instruction to run an unrelated sample check to clear a different failure.
"retry": "true", a Python variable, a command-line flag, or prose saying "retrying" is NOT equivalent.
Keep the actual failed check's meaning and failure exits; at most two corrective attempts.
Issue one execution call and read its result before choosing the next execution call. This is
agent guidance, not a runtime change, and the recorded omissions were separate calls, not batches.

Program SyntaxError/TypeError/ParseError under [exit code 1] means the program ran and failed:
the corrected execution requires retry:true. Malformed TOOL-CALL JSON means nothing executed:
correct that same JSON request per its feedback, without adding retry solely for JSON syntax;
retain an existing retry:true if it was already correcting a prior executed failure. No unrelated
tool while JSON correction is pending. A refused/unknown outcome, exhausted recovery or STOP is
not permission to retry: preserve evidence and obey the stop. If unable to correct before then,
task_block with the precise reason. Do not suppress exits or weaken checks to obtain a pass.

For CLOSURE, author only your own s1/s2_entry per the wake template. First identity_close has no
retry flag; only an actual format_error warrants corrected identity_close with retry:true, at
most two corrections. Stop after accepted filing. A command failure is not a closure-format
failure; storage/ownership refusal is not format_error. Never file someone else's reflection.
The lead should include the compact recovery checkpoint as an existing briefcase directive for
every SVG specialist so it is visible at every task AND closure wake. No identity or loop edit.

[ COMMAND_PATH_CONTEXT ]
read_file paths and run_command program paths can have different roots. In the observed tail-fill
integration, read_file could open outputs/T1/cat.svg from sprint scope, but the command's cwd was
outputs/T2; opening outputs/T1/cat.svg there raised FileNotFoundError. Resolve dependency paths from
the printed command cwd or use the explicitly granted absolute path. Inspect imports too: a stray
import q caused a second executed failure. Both were recovered. Guidance does not guarantee adherence.

[ FINAL_BYTE_MEASUREMENT ]
Hash and size the actual final file bytes after writing. Text-mode reading can normalize CRLF to LF;
read_text().encode() measures normalized text, not the artifact on disk. In the tail repair these
were 25545 versus 25860 bytes with different hashes. The integration metadata measured the disk
correctly. State comparison scope; preserve the earlier report and correct by attributed addendum.

[ ALGORITHM ]
1. Write a short scene contract: subject, requested support, viewBox, focal subject, travel direction,
   motion mode, visible entry/exit policy, gait period, scenery periods, and contact tolerance.
   Choose only the modules needed for the brief. The following are two common camera modes,
   not a claim that all possible camera movement must fit exactly one of them.

   The cat frames are SVG_CAT_BODY_CONSTRUCTION (body agent) and SVG_CAT_FACE_DETAILS (face agent).
   CAT_ONLY: the cat frames. A diagnostic baseline is allowed; do not add a fence or sky unrequested.
   FIGURE_MOVES: the cat frames + SVG_FIGURE_CROSSING; add SVG_BACKGROUND_DESIGN for a requested scene.
   SUPPORT_MOVES: the cat frames + SVG_BACKGROUND_SCROLL; add SVG_BACKGROUND_DESIGN as needed.
   BACKGROUND_ONLY: SVG_BACKGROUND_DESIGN; add SVG_BACKGROUND_SCROLL for moving scenery. No cat required.
   A mixed camera move must state and verify its relative velocities explicitly.

2. Solve the static silhouette and support geometry before secondary effects. Distinguish rear/front
   anatomy from far/near depth. Declare the layer order; intentional occlusion is not disconnection.

3. Prefer placement on an outer group and animation on its child. Use local joint coordinates.
   Explicit additive SMIL is also valid when the transform order is deliberate. Do not condemn
   every element carrying both transform and animateTransform. A reset which replaces placement
   unexpectedly is the failure. CSS pivots require an explicit coordinate/reference-box choice.

4. Check the source structurally: XML parses, IDs are unique, href/url/ARIA references resolve,
   expected animations exist, and keyTimes/values/splines agree. Report parser errors as errors.
   An empty reference set is valid for a simple drawing with no references; it cannot substitute
   for successfully extracting references from a file known to use them. Read UTF-8 explicitly.

   Parse the actual file after the initial SVG skeleton and after each substantive rewrite,
   before long geometry checks or integration. XML comments cannot contain two consecutive
   hyphens inside their content: use <!-- HEAD -->, never <!-- ---------- HEAD ---------- -->.
   The latter caused the first SVG Cat Polish cat to fail at line 242 despite valid-looking art
   source. A geometry calculation in a separate script cannot certify the SVG file it describes.

   In the existing Tasker command-recovery-v1 workflow, a failed run_command/run_tests leaves a
   pending failure. Read the error and inspect source with read_file (offset/limit) or list_dir.
   Fix your own active-task output with write_file. Rerun the corrected failed operation with
   retry=true on that tool call; at most two corrective attempts are allowed. If you cannot
   correct it, task_block with the exact reason. Do not launch a different diagnostic command
   without resolving the pending failure. Do not label an unrelated command retry=true just
   to clear the guard, suppress the failure exit, weaken the check, or claim closure prematurely.
   A parser check should return a failing exit when the document is invalid. This teaches the
   current tool protocol; it does not add retries, change permissions or alter runtime policy.
   Outside Tasker, follow the actual host's documented recovery protocol instead.

5. Render named times from each relevant animation clock. For stride period P, sample a full
   cycle at offsets 0, P/4, P/2, 3P/4 and near the repeat boundary; add joint extrema and stance
   transitions. Record begin offsets. Also inspect entry/exit and each scenery seam independently.
   Matching poses at arbitrary quarter and three-quarter scene times do not prove a broken gait:
   those times may land on the same stride phase. Sparse samples cannot prove every frame.

6. Inspect the cat, support and background separately and then together. Whole-image pixel changes
   can come from clouds alone. A moving cat crop may still show only body bob. Use leg transforms,
   named paw positions and phase-selected frames to establish gait. No universal pixel threshold.
   Keep the original, any diagnostic derivative, requested times and measured clocks distinguishable.

7. Review in the intended browser/embed host. Standalone rendering does not establish that a
   Markdown viewer or sanitizer will preserve animation. Provide a static/reduced-motion treatment
   when the destination requires it; test that treatment separately.

[ IMPLEMENTATION_NOTE_SVG ]
The transform mechanisms are specified, even when the cause of a historical failed sample remains
an inference. SMIL replacement and additive composition: https://www.w3.org/TR/SVG11/animate.html#AnimateTransformElement
CSS transform, origin and reference box: https://www.w3.org/TR/css-transforms-1/#transform-origin-property
For SMIL inspection, wait for the document timeline to load, pauseAnimations(), setCurrentTime(t),
then verify getCurrentTime() and animationsPaused() before capturing. These calls do not control
CSS or JavaScript animation clocks. https://www.w3.org/TR/SVG11/struct.html#InterfaceSVGSVGElement

[ SELF_CHECK ]
Q1: Must every animated SVG contain a cat and fence?
A1: No. Load only the requested subject, support and motion modules.
Q2: A far leg disappears behind the torso during part of a stride. Is it detached?
A2: Not necessarily. Inspect its joint and visible phases; deliberate depth occlusion is valid.
Q3: The same pose appears twice in a scene loop. Is that a failed walk?
A3: Not without the stride phases. Repeated cycles naturally revisit the same pose.
Q4: All pixels change between two screenshots. Do the legs work?
A4: That only proves image change. Inspect leg-specific motion and contact.
Q5: Why is <!-- ---------- HEAD ---------- --> invalid when <!-- HEAD --> is valid?
A5: XML forbids double-hyphens inside a comment's content. Parse the actual file early.
Q6: Your XML-check command failed. May the next shell diagnostic omit retry=true?
A6: No in this Tasker workflow. Use read tools to inspect, correct the output, and retry the failed
check with retry=true, within its bound; otherwise block. Do not use an unrelated successful
command to erase the pending error.

Q7: A command printed PASS before TypeError. Does the next corrected command need retry:true?
A7: Yes. Its final nonzero exit controls pending recovery, not the earlier stdout.
Q8: You recovered one failure, then a later command failed. Is retry now optional?
A8: No. That later failure opens a new episode. Check the actual outer JSON before sending.
Q9: Can a Python SyntaxError use the tool-JSON rule of not adding retry?
A9: No. The Python program executed and failed. Tool-JSON feedback means execution never began.
